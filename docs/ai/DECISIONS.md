# Решения

## 2026-10-03 — Память проекта

`docs/ai/` — единственный постоянный источник итогового знания о проекте. Перед задачей читаются все файлы этой памяти; изменения кода сопровождаются обновлением `CURRENT_STATE.md`, а завершённая задача — краткой записью в `CHANGELOG_AI.md`. Основание: прямое требование владельца проекта.

## 2026-10-03 — Граница первого этапа

Сначала согласуется план; до аппрува приложение не создаётся. Первый этап охватывает Header, главную страницу, Footer и настоящий интерактивный UI-макет `Altacod Radar`. Остальные страницы следуют после визуальной проверки главной. Основание: порядок из ТЗ и прямое требование владельца проекта.

План [FIRST_STAGE_PLAN.md](FIRST_STAGE_PLAN.md) одобрен владельцем проекта 2026-10-03.

## 2026-10-04 — Один frontend и демонстрационный Radar

Первый этап реализован одним Vite/React/TypeScript frontend. Radar — интерактивный макет с локальным состоянием и детерминированным расчётом заказа. Он не представлен как действующая система мониторинга клиента. Это даёт посетителю понятный пример будущего продукта без ложного обещания работающей интеграции. Данные отделены от UI, компонент Radar загружается отдельно.

## 2026-10-04 — Контакт и публичный адрес

До появления backend обращение открывает почтовое приложение с адресом, предоставленным владельцем. Не имитируем отправку формы. Telegram и MAX добавляются как дополнительные каналы после получения ссылок. Canonical и OpenGraph URL выводятся из `VITE_SITE_URL` или текущего origin: публичный домен пока не подтверждён. Первоначальный адрес `savkin@altacod.com` заменён 2026-10-04; его использование имеет статус **Superseded**.

## 2026-10-04 — Общий адрес для обращений

Почтовый адрес сайта — `info@altacod.com`, подготовленный владельцем проекта. Он используется во всех видимых ссылках, SEO-описании контакта и черновике обращения. Личный адрес больше не используется для новых заявок.

## 2026-10-04 — Проверки сборки

Каждый `npm run build` запускает typecheck и автотесты до Vite build. Причина: прямое требование владельца проекта обнаруживать сбои фич до сборки артефакта.

## 2026-10-04 — Страницы после главной

Разделы решений и отраслей получили обзорные маршруты и отдельные страницы с общими компонентами и собственным содержимым. Это делает навигацию понятной, а тексты и визуальную систему — согласованными без дублирования разметки. Демонстрационные сценарии отделены от реальных кейсов; `/cases` не заявляет несуществующие результаты.

## 2026-10-04 — Черновик обращения

Пока backend не создан, форма `/contact` готовит письмо по данным посетителя и открывает его по явному действию пользователя. Файл остаётся на устройстве: браузер не может вложить его в `mailto`, поэтому интерфейс прямо просит приложить файл вручную. Основание: не выдавать подготовку письма за отправленную заявку и не имитировать загрузку.

## 2026-10-04 — Хлебные крошки

Навигационный путь добавлен на все внутренние страницы. Для решений и отраслей он проходит через обзорный раздел; для остальных — прямо от главной. Путь формируется из маршрута и существующего контента, чтобы подписи не расходились с названиями страниц. Текущая страница не является ссылкой, крошки имеют доступную метку навигации. Основание: посетителю нужен понятный способ вернуться к разделу, из которого он пришёл.
