# Решения

## 2026-10-03 — Память проекта

`docs/ai/` — единственный постоянный источник итогового знания о проекте. Перед задачей читаются все файлы этой памяти; изменения кода сопровождаются обновлением `CURRENT_STATE.md`, а завершённая задача — краткой записью в `CHANGELOG_AI.md`. Основание: прямое требование владельца проекта.

## 2026-10-03 — Граница первого этапа

Сначала согласуется план; до аппрува приложение не создаётся. Первый этап охватывает Header, главную страницу, Footer и настоящий интерактивный UI-макет `Altacod Radar`. Остальные страницы следуют после визуальной проверки главной. Основание: порядок из ТЗ и прямое требование владельца проекта.

План [FIRST_STAGE_PLAN.md](FIRST_STAGE_PLAN.md) одобрен владельцем проекта 2026-10-03.

## 2026-10-04 — Один frontend и демонстрационный Radar

Первый этап реализован одним Vite/React/TypeScript frontend. Radar — интерактивный макет с локальным состоянием и детерминированным расчётом заказа. Он не представлен как действующая система мониторинга клиента. Это даёт посетителю понятный пример будущего продукта без ложного обещания работающей интеграции. Данные отделены от UI, компонент Radar загружается отдельно.

## 2026-10-04 — Контакт и публичный адрес

До появления backend обращение открывает почтовое приложение с адресом, предоставленным владельцем. Не имитируем отправку формы. Telegram и MAX добавляются как дополнительные каналы после получения ссылок. Canonical и OpenGraph URL выводятся из `VITE_SITE_URL` или текущего origin. Первоначальный адрес `savkin@altacod.com` заменён 2026-10-04; его использование имеет статус **Superseded**.

## 2026-10-04 — Общий адрес для обращений

Почтовый адрес сайта — `info@altacod.com`, подготовленный владельцем проекта. Он используется во всех видимых ссылках, SEO-описании контакта и черновике обращения. Личный адрес больше не используется для новых заявок.

## 2026-10-04 — Проверки сборки

Каждый `npm run build` запускает typecheck и автотесты до Vite build. Причина: прямое требование владельца проекта обнаруживать сбои фич до сборки артефакта.

## 2026-10-04 — Страницы после главной

Разделы решений и отраслей получили обзорные маршруты и отдельные страницы с общими компонентами и собственным содержимым. Это делает навигацию понятной, а тексты и визуальную систему — согласованными без дублирования разметки. Демонстрационные сценарии отделены от реальных кейсов; `/cases` не заявляет несуществующие результаты.

## 2026-10-04 — Черновик обращения

Пока backend не создан, форма `/contact` готовит письмо по данным посетителя и открывает его по явному действию пользователя. Файл остаётся на устройстве: браузер не может вложить его в `mailto`, поэтому интерфейс прямо просит приложить файл вручную. Основание: не выдавать подготовку письма за отправленную заявку и не имитировать загрузку.

## 2026-10-04 — Хлебные крошки

Навигационный путь добавлен на все внутренние страницы. Для решений и отраслей он проходит через обзорный раздел; для остальных — прямо от главной. Путь формируется из маршрута и существующего контента, чтобы подписи не расходились с названиями страниц. Текущая страница не является ссылкой, крошки имеют доступную метку навигации. Основание: посетителю нужен понятный способ вернуться к разделу, из которого он пришёл.

## 2026-10-04 — Домены и порядок миграции

Публичный корпоративный сайт предназначен для `altacod.com`, а действующий каталог — для `products.altacod.com`. Новый сайт разворачивается отдельным приложением Coolify. Перед изменением Caddy фиксируются работающие маршруты и конфигурация, затем проверяется каталог на новом имени и только после этого переключается apex. Остальные приложения Coolify и их маршруты не меняются. Основание: указания владельца и необходимость сохранить действующий каталог.

## 2026-10-04 — Витрина и статические метаданные

Витрина `/projects` содержит шесть выбранных владельцем продуктов и ссылается на их страницы в каталоге через `products.altacod.com`. Метаданные маршрутов хранятся в `src/data/routeMeta.json`: один набор используется браузером и скриптом генерации HTML, sitemap и robots.txt. Это позволяет показывать корректные title, description и OpenGraph при прямом запросе страницы. Иллюстрации карточек остаются условными; их можно заменить подтверждёнными изображениями продуктов.

## 2026-10-04 — Разделение серверов

Уточнена топология: Coolify расположен на домашнем сервере без белого IP, Timeweb/Caddy — отдельный публичный reverse proxy. Существующий SSH-ключ к домашнему серверу не является доступом к Timeweb. Для Timeweb нужен отдельный ключ; изменения Caddy выполняются только после подтверждения его назначения и сохранения текущих маршрутов.

## 2026-10-04 — Точка изменения публичных маршрутов

Проверено: nginx на Timeweb слушает внешний 443 и передаёт TLS-поток в локальный Caddy на 8443; Caddy слушает также HTTP 80 и содержит блоки доменов. Для переноса `altacod.com` и добавления `products.altacod.com` выполнены точечные изменения Caddyfile после сохранения копии и валидации. Конфигурация nginx для этих доменов не менялась. Основание: прочитанные конфигурации и работающие службы Timeweb.

## 2026-10-04 — Раздельные приложения и маршрутизация по Host

Корпоративный сайт работает в отдельном приложении Coolify с Host `altacod.com` и портом 80; каталог сохраняет своё приложение с Host `products.altacod.com` и портом 3000. Caddy передаёт соответствующий Host домашнему серверу. Внутренний hostname каталога `altacod-apps.sslip.io` сохранён для служебной доступности. При переключении главного домена менялись только два Host-заголовка в блоках apex; остальные маршруты остались на прежних upstream. Основание: сохранить существующие проекты и дать каждому сайту собственный публичный адрес.

## 2026-10-04 — Переход на HTTPS

Адресные HTTP-блоки `altacod.com`, `www.altacod.com` и `products.altacod.com` возвращают 308 на соответствующий HTTPS-адрес; `www` переходит сразу на `https://altacod.com`. Остальные блоки Caddy не менялись. Основание: критерий миграции требует постоянного перехода с HTTP и единого главного адреса.

## 2026-10-04 — Раздельная аналитика сайтов

Новый сайт услуг использует новый счётчик Яндекс Метрики `113399075`, предоставленный владельцем. Действующий счётчик каталога остаётся с каталогом при переносе на `products.altacod.com`, чтобы сохранить его историю и цели. Для React Router счётчик инициализируется с `defer: true`, а просмотры отправляются на реальных переходах маршрутов. Код загружается только на публичном домене, поэтому локальные проверки и предпросмотр не попадают в статистику. Основание: разные цели двух сайтов и инструкция Яндекса для SPA.

## 2026-10-04 — Перенос старых ссылок каталога

После переключения главного домена старые адреса `altacod.com/apps/*` перенаправляются nginx нового сайта на `products.altacod.com/apps/*` кодом 308 с сохранением пути и параметров запроса. Основание: ранее опубликованные ссылки на продукты должны оставаться рабочими, а страницы каталога — индексироваться только на новом домене.

## 2026-10-04 — Прямая отправка обращений

Решение «Черновик обращения» получит статус **Superseded** после выпуска новой формы. Статический сайт сохраняется; почтовая отправка вынесена в отдельное API-приложение того же проекта Coolify, а Caddy направит в него только `/api/contact`. Это позволит проверить API до переключения формы, не затрагивая каталог и соседние сервисы. Mailu на Timeweb доступен с домашнего сервера по SMTP TLS на порту 465 с действительным сертификатом; порт 587 недоступен. Отправитель — авторизованный ящик `noreply@altacod.com`, получатель — `info@altacod.com`, ответ — на адрес посетителя через `Reply-To`. Пароль задаётся только серверной переменной Coolify. Клиент и сервер проверяют email; API ограничивает тип и размер файла, число обращений и обрабатывает ошибку SMTP без ложного подтверждения отправки.

## 2026-10-04 — Конкретные примеры на главной

Первые три блока сохраняют прежний порядок и визуальную систему. Абстрактные описания заменены знакомыми владельцу бизнеса ситуациями; в схеме показан короткий пример сигнала о марже, а после карточек решений добавлены четыре компактных сценария. Это поясняет предмет услуги без расширения позиционирования за пределы автоматизации вокруг 1С. В интерфейсе сохранено написание «ИИ».
